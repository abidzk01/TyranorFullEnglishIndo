# patches/ — minimal patches against the SDL2 dependency

These patches bring the official SDL2 2.32.10 sources into the state required for "bundling into Tyranor Next".
The dependency sources are **not distributed with the main repository**: `scripts/build-xsys35.sh` extracts the
official tarball into a build directory outside the repository (`<build-dir>/third_party/SDL2`) and applies the
following patches one by one, in filename order, to the **freshly extracted clean sources**
(validated first with `git apply --check` / `patch --dry-run`, applied on success; skipped on repeated runs when the
content re-check passes). The "target file" paths in the table below are relative to `<build-dir>/third_party/`.

| Patch | Target file | Effect |
| --- | --- | --- |
| `0001-sdl2-jni-prefix-app32.patch` | `third_party/SDL2/src/core/android/SDL_android.c` | `SDL_JAVA_PREFIX` macro + the 4 register_methods class path strings `org/libsdl/app` → `org/libsdl/app32` in `JNI_OnLoad` |
| `0002-sdl2-hidapi-jni-prefix-app32.patch` | `third_party/SDL2/src/hidapi/android/hid.cpp` | HIDAPI's `SDL_JAVA_PREFIX` macro `org_libsdl_app` → `org_libsdl_app32` (HIDDeviceManager exports its JNI methods by symbol name, so it must stay in sync; otherwise the app32 Java layer crashes with `UnsatisfiedLinkError` right at startup) |

Background: the ONS plugin's SDL2 2.26.3 Java layer (`org.libsdl.app`) cannot be mixed with the 2.32.10 native
side (hard version check in `onCreate`), so this engine's Java layer is renamed wholesale to `org.libsdl.app32`
(generated by `../scripts/sync-app32-java.sh`), and the native-side prefix must be renamed in lockstep.
See §3 of `../BUILD.md`.

## Re-applying

On **unmodified** official SDL2 2.32.10 sources (`<build-dir>` is the build directory of `build-xsys35.sh`,
default `${TMPDIR:-/tmp}/xsys35-build`):

```bash
cd <build-dir>/third_party/SDL2
patch -p1 < <repo>/engine/xsystem35/patches/0001-sdl2-jni-prefix-app32.patch
patch -p1 < <repo>/engine/xsystem35/patches/0002-sdl2-hidapi-jni-prefix-app32.patch
```

## Verification (exhaustiveness of the rename surface)

```bash
cd <build-dir>/third_party/SDL2
grep -rn "org/libsdl/app" src/ include/     # should only show org/libsdl/app32/...
grep -rn "org\.libsdl\.app" src/            # should be 0 lines
grep -rn "org_libsdl_app" src/ include/     # should only be the 2 macros (value ...app32) + 1 comment
```

## Renames that are not patches

The output-name renames of `libSDL2x.so` (SONAME = `libSDL2x.so`) and `libSDL2_mixer_xs35.so` are done in
`../android-host/CMakeLists.txt` with `set_target_properties(... OUTPUT_NAME ...)`, without touching the upstream
sources (measured: the SONAME matches the file name, so no `-Wl,-soname` correction is needed), hence no patch files
are produced for them.
